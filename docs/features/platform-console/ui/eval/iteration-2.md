## Phase 1 — Reasoning Audit（独立推理审计）

**问题 → 方案**: 11 个 UF 全部有对应 Component，Placement 与 PRD Page Composition 一一相符；迭代 1 的流程级矛盾（登录绕过租户选择）已修正，UF-1 → UF-11 → UF-3 的分流链条现在自洽（含强制改密插入点「改密成功后方可进入租户选择」）。

**方案 → 证据**: 发现一条**修订新引入的自相矛盾**（HARD-RULE 扣分项）：

- UF-4 Data Binding:「username（**1–64**，正则 ^[a-z][a-z0-9_-]{2,31}$）」
- 同一单元格内：正则 `^[a-z][a-z0-9_-]{2,31}$` 限定总长 **3–32** 字符；PRD UF-4 亦明确「3–32 字符，`^[a-z][a-z0-9_-]{2,31}$`」。

「1–64」与其自身正则、与 PRD 三方矛盾——按字面实现前端会允许 64 字符用户名而 eiam 按 32 拒绝。这是本轮最高优先级修复项（迭代 1 该字段写作与 PRD 一致的正则、未带错误长度，本轮引入了错误长度标注）。

**证据 → 成功标准**: 设计无独立成功标准，无冲突。

**SC/状态簇一致性核查**（按协议对 States/Interactions/Data Binding 做簇内双向推导）:

- UF-11 零租户「受限���作台（即 UF-3 受限视图态）」↔ UF-3 受限视图已定义 → 满足。
- UF-6「活跃会话数列 active_session_count…与禁用校验同一字段」↔ 禁用被拒态「提示活跃会话数（>0 不可禁用）」→ 同源满足（迭代 1 的「用户数 vs 活跃会话数」两概念混淆已消除）。
- 文案契约各 key 与引用组件逐条核对一致（tenant.none/delete.blocked_org/session.expired 均逐字匹配）；唯一例外：UF-2 States「原地 toast「无权限」」≠ 契约 forbidden「无权限执行该操作」——契约自称「实现不得改写措辞」，设计自己的状态表先改写了。
- UF-2 Interactions 表无「切换租户」行，而 UF-11 写「登录后切换租户 | 经 UF-2 顶部租户选择器 | 切换后上下文刷新」——选择器的行为定义在非所属组件的表里，UF-2 自身读者无从接线（转入 Impl）。
- UF-9「撤销生效（延迟 ≤30s 提示）」：生效窗口内表格行显示什么（原状态？待生效徽标？）无人负责（转入 Impl）。

**Phase 1 前置锚点（转入后续评分/blindspot）**:
1. username 1–64 vs 正则 3–32 三方矛盾（计入 RC 跨区矛盾）。
2. 文案契约自称「全站文案唯一口径」但 13 个 key 不含任何字段级校验文案；UF-1 Error 行把「用户名或密码错误」套在含 MFA 失败的通用 Error 态上，契约无 mfa 失败 key；UF-6 禁用被拒文案无 key（转入 blindspot）。
3. 租户切换（UF-11）与 401（UF-2）对未提交草稿的策略不对等：401 已决「丢弃未提交草稿」，切换租户仅「上下文刷新」，编辑中切换是否丢草稿未决（转入 blindspot）。

**Edge case handling: 25/50**

已覆盖：E1（改密态+一次性密码）、E2/E9（锁定+倒计时+逐字文案+副行）、E3（受限视图+URL 直入提示+管理员豁免）、E4（单租户 toast 自动分流）、E8（WebAuthn 隐藏入口）、E10（正则前端拦截——尽管长度标注错误）、E11×3（org 弹窗确认置灰/role/policy 均有文案同源）、E12（降级提示+各页 Error）、空凭据拦截、401 丢草稿、授权三元组预检、策略 JSON 双层校验、租户禁用会话数校验。

- username「1–64」↔ 自身正则/PRD 3–32（Phase 1 锚点 1，-5）。
- UF-2「toast「无权限」」↔ 契约 forbidden「无权限执行该操作」+「实现不得改写措辞」（-5；与迭代 1 -30 级流程矛盾不同量级，按措辞冲突计）。

### 2. User Experience — 206/250（终端用户视角）

**Information hierarchy: 66/80**

- 页面骨架扫描动线成熟一致：页面头（标题+主操作）→ 过滤区 → 主表格；登录 max-w-sm 居中卡；工作台「欢迎横幅 → 应用卡片」；UF-4 过滤维度已从泛指的「过滤」收敛为「角色过滤」。
- 扣分（-14）：UF-3「顶部欢迎横幅（H2 欢迎 + 我的信息）」——「我的信息」区块内容/字段数/密度仍全部未定义，无法评估其层级与视觉权重（-8）；表格列优先级/省略策略全文档未提，长 DN/授权主体列会破坏扫描节奏且无截断约定（-6）。

**Interaction intuitiveness: 62/80**

- 惯例模式选型全部正确且新增部分提升了可预期性：树键盘导航、Dialog focus trap + Esc + 焦点归还、锁定倒计时 aria-live、单租户「toast 短暂提示」（形态已定名，-1 余留：时长未定）、401 明确「丢弃未提交草稿」是果断的用户预期管理。
- 扣分（-18）：应用切换器「新标签/同标签跳转」仍未决——这是用户心智模型的基本决策（保工作台上下文 vs 单向导航），不是实现细节（-6）；UF-4「列表即时过滤」前端当前页过滤还是服务端查询仍未决，分页场景下二者体验完全不同（-5）；UF-5「树刷新」/UF-6「刷新」仍无时限，与 UF-4/UF-8 的「≤2s 刷新」同类操作不同承诺（-3）；删除/禁用确认强度未分级——「删除确认」是单击还是输入对象名，破坏性操作的摩擦度未设计（-3）；单租户 toast 时长（-1）。

**Accessibility: 78/90**

- 新增 Accessibility 小节实质覆盖了迭代 1 的全部空白：键盘（树三键位、表格 Tab、Dialog 焦点圈闭/归还、登录 Tab 序）、表单（显�� label、必填 *、aria-describedby 错误关联）、状态播报（role="alert"、aria-busy、aria-live polite 覆盖锁定倒计时与「撤销生效（≤30s）」）、图标替代（导航图标+文字、icon-only 带 aria-label）。这部分从 25/90 的废墟重建为合格线以上。
- 扣分（-12）：
  - **对比度断言可被自家数值证伪（-8）**：「文本一律取色彩 token 组合，明暗两主题均满足 WCAG AA（正文 ≥4.5:1…）」。实测其 destructive 组合：primary-foreground #fafafa（L≈0.955）叠 destructive #ef4444（L≈0.229）≈ **3.6:1**，destructive 文本叠 Light 背景 ≈ 3.76:1——均低于正文 4.5:1。按钮/徽章 destructive 变体直接命中此组合，承诺与 token 表相互矛盾。
  - 表格语义化（th scope/caption）与分页器的键盘可达性未提（-3）；toast 出现时焦点策略未提（-1）。

**小计**: 66 + 62 + 78 = **206/250**。

### 3. Design Integrity — 215/250（设计师视角）

**Design system adherence: 68/80**

- 强项维持且增强：token 表完整；语义 Token 映射表落地了「组件库无关」承诺（「若最终组件库不含 Tailwind，仅替换映射右列，语义值不变」）；主题策略已决策（默认 Light + prefers-color-scheme 跟随）；Do/Don't 防走样清单保留。
- 扣分（-12）：语义色缺口未补——调色板仍只有 destructive，「启用/禁用/锁定」「连接失败」「降级提示」所需的 success/warning 角色缺失，徽章「default/secondary/outline/destructive 四变体」无对应变体，状态着色将被迫硬编码、正撞自家 Don't（-6）；字体仍自相矛盾于单一家族惯例（正文系统栈 vs 标题 Inter）且 16px 正文对高密度表格偏大、表格字号未���明（-4）；深度声明与对话框规格相互 tension：「无阴影系统，靠背景透明度 + 边框 + 对话框遮罩表达层级」vs「内容 bg-background 圆角 8px **阴影**」——对话框是唯一例外但未被声明为例外（-2）。

**Visual coherence: 79/90**

- 全站共享单一主布局，跨页导航元素一致（未触发 -30 规则）；「页面头 + 表格 + Dialog」模式贯穿十个页面；两级圆角（6/8px）与无阴影体系统一；UF-1 帮助入口已落绑定（help_url），迭代 1 的无归宿元素消除。
- 扣分（-11）：状态列视觉语言仍无规范——「状态」在 UF-4 是三态、UF-6 两态、UF-7 是开关，徽章色映射未定义，同一概念跨页不同形（-6）；反馈时限口径仍分裂（UF-4/8「≤2s」vs UF-5/6 泛「刷新」，-3）；图标无清单来源，八个菜单图标与页内 icon-only 按钮取自哪个图标集未声明（-2）。

**State completeness: 68/80**

## Phase 3 — Blindspot Hunt

1. **[blindspot] 文案契约自称「唯一口径」，覆盖面却不含最高频的三类文案** — 原文：「全站文案唯一口径，实现不得改写措辞」。该契约仅 13 个 key，全部是系统级错误；而 (a) 字段级校验文案（用户名格式、LDAP 地址/端口格式、JSON 语法错、必填项）一个 key 都没有——a11y 节又要求「字段校验错误经 aria-describedby 关联到错误文案」，错误文案本身无源头；(b) UF-1 Error 行「表单顶部统一中性错误条「用户名或密码错误」」按 PRD 该态触发条件是「凭据错误/**MFA 失败**」——MFA 码错误将显示「用户名或密码错误」，文案错位且契约无 mfa key；(c) UF-6 禁用被拒「提示活跃会话数（>0 不可禁用）」无 key。Reasoning audit flagged this independently of dimension scoring. 必须改进：补字段校验/MFA/禁用被拒 key，或将契约口径改为「系统级文案唯一口径」并声明校验文案的维护位置。

2. **[blindspot] 上下文销毁策略在 401 与租户切换两个同域场景下不对等** — 原文：UF-2「过期（401）…中断请求、**丢弃未提交草稿**、跳 /login；v1 不保留编辑上下文」vs UF-11「登录后切换租户 | 经 UF-2 顶部租户选择器 | **切换后上下文刷新**」。用户在 Dialog 里填一半策略 JSON 时切换租户：草稿保不保留、「上下文刷新」是整页 reload 还是数据重取、Dialog 是否关闭——全部未定义。401 场景证明了作者有能力也认为应当就此决策，切换租户场景（同一把未提交草稿悬在同样的悬崖边）却被漏掉。Reasoning audit flagged this independently of dimension scoring. 必须改进：租户切换复用同一草稿策略并写明刷新形态。
