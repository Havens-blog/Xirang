# 3.4: M2 E2E：租户分流（E3/E4/E5）+ 单点跳转 + 双侧登出

## Description
真实浏览器验证租户分流与跨应用会话：E3 零租户受限、E4 单租户自动、E5 多租户切换、应用切换单点跳转（不重复登录）、双侧单点登出（Story 6）。证据回填 acceptance.md。

## Reference Files
- docs/features/platform-console/prd/prd-spec.md — M2 出口判据（E3/E4/E5 通过；单点跳转与双侧登出 Story 6 通过） (ref: Milestones)
- docs/features/platform-console/design/tech-design.md — Integration Specs 2/3（SSO 应用切换、双向单点登出） (ref: Integration Specs)

## Acceptance Criteria
- [ ] E3：零租户用户登录 → 受限工作台（仅欢迎+我的信息）；URL 直入管理页提示「无所属租户」不白屏；平台管理员豁免可进管理页
- [ ] E4：单租户用户 → 自动选定直达工作台（无选择页停留）
- [ ] E5：多租户经切换器重选 → tenant_id 写回 + location.replace 刷新数据
- [ ] 单点跳转：应用切换器新标签开 e-cam-web 不重复登录；双侧登出：任一侧登出 → 另一侧下一请求 401 收敛回控制台登录页
- [ ] 证据回填 acceptance.md 对应 M2 场景项（Playwright 用例链接）

## User Stories
Story 3（零租户/租户边界）、Story 4（角色授权逐请求判定，骨架）、Story 6（任一侧登出双侧失效）承接。

## Hard Rules
验收宿主必为 nginx 同域形态；双侧登出断言须真实双会话验证，不得 mock。

- 仅新增：`e2e/` 租户分流/SSO/登出场景用例。跨标签页一致性（写前守卫 + 回读）的负向场景在此补一条（错租户写被守卫阻断）作为 3.1 的验证。
