# 2.12: M1 E2E：登录正/负/边界（E1/E2/E8/E9）

## Description
真实浏览器（Playwright，chromium）验证登录闭环正/负/边界：登录正向、错误凭据中性文案、E2 锁定、E8 passkey 不可用、E9 MFA 锁定、E1 强制改密骨架。证据回填 acceptance.md。

## Reference Files
- docs/features/platform-console/design/tech-design.md — Testing：E2E 硬性、验收宿主必为 nginx 同域、E1–E12 正向+负向+边界≥1/3 (ref: Testing)
- docs/features/platform-console/prd/prd-spec.md — M1 出口判据（E1/E2/E8/E9 真实浏览器通过） (ref: Milestones)

## Acceptance Criteria
- [ ] 登录正向：有效密码 → 会话写入 → 分流（0/1/≥2）；LDAP/passkey 正向按 eiam 可用方式覆盖
- [ ] 负向：错误凭据 → 统一「用户名或密码错误」不泄账号（重试保留输入、不白屏）
- [ ] E2：连续 5 次密码错 → 锁定 15 分钟 + 剩余倒计时（auth.account_locked 文案计数）
- [ ] E8：WebAuthn 不可用浏览器 → passkey 入口隐藏 + 提示、无 JS 报错
- [ ] E9：MFA 连续 5 次失败 → 锁定（与 E2 同口径）；E1 强制改密骨架（首次登录触发改密表单）
- [ ] 每场景附 Playwright 用例链接回填 acceptance.md（对应 M1 场景项）

## User Stories
Story 1（登录进入工作台、passkey 不可用、MFA 锁定、登录失败保留输入）全 AC。

## Hard Rules
验收宿主必为 nginx 同域形态（:8888/console），禁止 dev server 判定；证据须真实浏览器执行，不得用 mock 会话替代。

## Implementation Notes
- 仅新增：`e2e/` 登录场景用例。eiam 不可用（E12）与零租户/受限视图的 E2E 归 M2（3.4）；本任务聚焦登录态。
- 浏览器矩阵仅 chromium（与内网统一浏览器一致）。
