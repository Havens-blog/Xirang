# 2.6: router + 全局守卫链

## Description
落地路由表 + 全局 beforeEach 守卫链：① cookie 缺失 / profile 拉取失败 → /console/login ② mustSelectTenant → /tenant-select ③ permissions 裁剪不通过 → 403 页（与菜单裁剪同口径）④ 放行 → 记录「页面进入租户快照」。路由全部 `import()` 懒加载。

## Reference Files
- docs/features/platform-console/design/tech-design.md — SPA 内部组件关系中的 router 全局守卫链四步 (ref: Architecture)
- docs/features/platform-console/design/tech-design.md — Integration Specs 6 写前守卫/租户快照机制 (ref: Integration Specs)

## Acceptance Criteria
- [ ] 11 路由注册（/login /workbench /users /users/:id /organizations /tenants /identity-sources /roles /roles/:id /authorizations /policies /tenant-select），子页含返回导航
- [ ] beforeEach 四步：① cookie 缺失或 profile 失败 → 跳登录 ② mustSelectTenant → 跳 /tenant-select ③ permissions 裁剪不通过 → 403 页 ④ 放行并把 currentTenantId 记入模块级单值快照
- [ ] 401 后中断在途路由请求、list store 复位 loading/error（403 原地、401 跳转的区分）
- [ ] 路由级懒加载（全 import()），403 页与菜单裁剪同口径（权限裁剪只读不渲染增删改入口的类别在守卫层可判定）

## User Stories
Story 1（登录→工作台）、Story 3（越权 403 原地）、Story 5（只读/审计菜单裁剪 + URL 直入 403） 的守卫承接。

## Hard Rules
守卫链为唯一权限裁剪入口，与各 UF Validation Rules 的菜单可见性口径逐项一致；快照非持久化、非第二份租户真相存储。

## Implementation Notes
- 仅修改：`src/router/`（routes + guards）。写前守卫的快照取值依赖 user store 的 currentTenantId（2.7）。
- 403 页面文案走 2.5 文案契约 forbidden；快照机制被 3.1 写前守卫消费。
