# 4.4: 租户管理页（UF-6）：禁用前置活跃会话数校验

## Description
落地 /tenants（仅平台管理员可见）：`tenantList` store + `tenants.ts` api（list/create/update/delete + switch）。租户表格（名/状态/活跃会话数/操作）、新增/编辑/禁用、禁用前置「未过期会话数=0」校验（被拒显示活跃会话数）。

## Reference Files
- docs/features/platform-console/ui/ui-design.md — 租户管理 UF-6：Layout/States（禁用被拒 tenant.disable_blocked）/Interactions/Data Binding（active_session_count） (ref: 租户管理)
- docs/features/platform-console/design/tech-design.md — A 档 tenant 端点、Tenant 模型、禁用前置会话计数（现不返回 → Phase 0 核查） (ref: Interfaces / Data Models)

## Acceptance Criteria
- [ ] tenantList store（统一契约）+ tenants.ts api（list/create/update/delete）+ 写前守卫/回读接入
- [ ] 租户表格：租户名/状态（启用/禁用 badge）/活跃会话数/操作；分页（复用 E7 边界）
- [ ] 禁用前置：活跃会话数=0 才可禁用，不满足则拒绝并显示活跃会话数（tenant.disable_blocked，{n}=active_session_count 与列同源）
- [ ] 新增/编辑：租户名 1–64 字符 + 全局唯一（validation.name_exists 冲突提示）
- [ ] 仅平台管理员可见/可操作（菜单 + 路由守卫双重口径，只读/审计亦不渲染）

## User Stories
Story 2（租户增删改查）、Story 5（只读角色不可见租户管理）承接。

## Hard Rules
禁用前置为硬门槛：活跃会话数 >0 不得禁用；租户管理入口仅平台管理员渲染。

## Implementation Notes
- 仅新增：`src/views/tenants/`、`src/stores/tenantList.ts`、`src/api/tenants.ts`。
- 活跃会话数端点：tenant/list 现不返回（Phase 0 核查）；无端点则降级为「禁用请求被 eiam 拒绝 + 拒绝消息中的活跃会话数展示」承接（见 Data Models 注释）。
