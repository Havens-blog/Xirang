# 2.4: 请求层 eiamAxios + 错误处理（unwrapEnvelope/ApiError）

## Description
落地 `api/request/eiam.ts`：eiamAxios 实例（withCredentials、cookie→Bearer 注入、15s 超时、401 → redirectToLogin 防抖）+ 单入口 `unwrapEnvelope<T>()` + `ApiError`/`ErrorKind`/`FieldErrors` + 错误码分类学。全部 api 客户端函数必经 unwrapEnvelope。

## Reference Files
- docs/features/platform-console/design/tech-design.md — Error Handling：ApiError/ErrorKind/FieldErrors 类型、两种错误形态统一解包、错误码分类学表、文案契约透传 (ref: Error Handling)
- docs/features/platform-console/design/tech-design.md — eiamAxios 拦截器模式（授权/响应拦截、401 防抖） (ref: Architecture)

## Acceptance Criteria
- [ ] eiamAxios：withCredentials true、timeout 15s、请求拦截 cookie→Bearer 注入、响应拦截 401→redirectToLogin（isRedirectingToLogin 防抖，继承现仓同款）
- [ ] unwrapEnvelope：① HTTP 2xx + code!=0 → ApiError（按分类学映射 kind，带业务 code）② 非 2xx 可解析 Envelope → 取 {code,msg} 抛同一 ApiError ③ 不可解析 → 按 HTTP 状态映射 kind
- [ ] ApiError（kind/code/httpStatus）+ ErrorKind + FieldErrors 类型；六个 kind 映射：401→unauthorized（跳登录+清在途）、403→forbidden（原地）、400/422→validation（FieldErrors）、409→conflict、网络/超时/5xx→unavailable、其余→unknown
- [ ] api 层零租户状态、参数进类型出纯调用；错误经 ApiError 上抛由 store 归位 error/FieldErrors

## User Stories
No direct user story mapping.（横向基础设施）

## Hard Rules
401 收敛不清共享 cookie；视图层只 catch 唯一 ApiError，不得绕过 unwrapEnvelope 直连 axios。

## Implementation Notes
- 仅修改：`src/api/request/eiam.ts`、`src/api/types/`（ErrorKind/ApiError 类型）。eiamAxios 为拷贝面文件，登记 shared-hashes.json。
- 业务码值透传文案契约 key；状态×code→kind 对照表以 Phase 0（1.1）产出为准，未产出前按 HTTP 状态优先。
