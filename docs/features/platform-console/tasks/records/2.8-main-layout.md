# Task Record: 2.8 主布局 MainLayout（侧边栏分组菜单 + header）

## Summary
Implemented the MainLayout shell (UF-2): a collapsible sidebar (220px↔64px, 300ms transition, <1024px drawer) with a 3-group 8-item grouped menu clipped by role (platform_admin 8 / readonly_audit 6 / tenant_admin 4 / normal 1; tenants & policies admin-only double-lock per Hard Rule), logo area routing to workbench. A 56px header with collapse button, breadcrumb (home/current page from sidebar active item), theme toggle (moon/sun), gradient user avatar + username, and a logout dropdown calling POST /api/iam/user/logout + resetState + redirect to /login. Tenant selector and app switcher are placeholder mount points pending task 3.1; zero-tenant restricted state disables the tenant slot (shows 无所属租户) and hides the app switcher. 403 surfaces as an in-place toast via a hc:forbidden window event (layout provides the toast承接; request-layer wiring deferred to avoid touching the locked eiam.ts copy-face); 401 redirect is handled by the existing eiamAxios response interceptor. App.vue mounts MainLayout as an async, code-split component only for matched non-public routes so its element-plus dependency does not enter main.ts's synchronous graph (keeps the 2.2 main-assembly smoke test green). vite.config inlines element-plus in vitest so its CSS imports resolve in the test graph.

### Key Decisions
- Role clipping uses inferRole(isAdmin, tenantsCount): isAdmin→platform_admin; tenants.length===0→normal (restricted); else→readonly_audit (provisional). tenant_admin vs readonly_audit distinction is provisional pending the parity §5 permission vocabulary; ROLE_VISIBILITY already encodes all four sets so the matrix is refinable without touching SidebarMenu once permission codes land.
- tenants/policies carry adminOnly:true as a Hard Rule double-lock alongside the role-visibility sets, so a future role-set edit cannot accidentally render them for non-admins.
- App.vue renders MainLayout only when route is matched AND non-public, and loads it via defineAsyncComponent — this keeps element-plus out of main.ts's sync module graph (avoids the 2.2 main-assembly smoke test timing out / tearing down mid-chunk-load).
- vite.config test.server.deps.inline includes /element-plus/ so its ESM .css imports resolve under vitest (was 'Unknown file extension .css') and are stubbed to empty modules (no assertion pollution).
- 403 toast is provided by MainLayout via a hc:forbidden window event + ElMessage with the forbidden contract text; the request layer (eiam.ts) is a shared-hashes.json-locked copy-face and is not modified in this task — 4.x/5.x store catch paths will dispatch hc:forbidden.
- Tenant selector and app switcher are disabled/hidden placeholder slots in AppHeader; actual TenantSelector shared component lands in task 3.1.
