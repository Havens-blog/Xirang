## Key Decisions
- **REAL 抓出的契约 bug（本次修复）**：eiam POST /api/iam/policy/create 成功响应不回传
  id（eiam/internal/web/policy/handler.go:201 `ginx.Result{Msg:"创建成功"}` 无 Data，
  实测 data:null）——旧 createPolicy 按 `unwrapEnvelope<number>` 永久得 null → store.create
  返回 null → 视图误判失败（对话框不关、提示「新增策略失败」），但策略实际已创建、列表已
  刷新。修复：createPolicy → Promise<void>（信封 code==0 即成功）；store.create →
  Promise<boolean>；PolicyList submitEdit 据布尔判定。JSON 老路径同享此修复
- **manifest gate 实测口径**：服务端 Needs manifest+menus_by_urns 双码，但 dev admin
  profile.permissions 只有 manifest（132 码，无 menus_by_urns）而请求仍 200（super 豁免）
  —— 客户端若要求双码则 REAL 上永不加载词表；改为 manifest 单码 gate + 失败降级，
  词表退化不阻断编辑（policy/create 本身 Needs manifest，见 handler.go:44，与编辑器
  gate 对齐）
- 词表真实规模：132 动作（含 cmdb:* 跨服务能力，非仅 iam:*）+ 2 services；菜单视图
  字段（has_menu/menu_urns）归一保留但不消费（P1）
- 图形化编辑边界：condition 亦为结构校验字段，图形化只读展示 + JSON 编辑；el-select
  allow-create 兜自由输入（词表缺项/无词表均可编辑）
- 输出口径：serializeStatementsJson 产出保持规范复数形（与 parseStatementsJson 同源），
  提交校验零改动沿用 5.3 口径
