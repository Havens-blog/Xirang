# 5.3: 策略管理页（UF-10）：Statement 表单 + schema 校验

## Description
落地 /policies（仅平台管理员）：`policyList` store + `policies.ts` api（list/create/update/delete）。表格（策略名/Effect/绑定对象数/操作）+ 编辑 Dialog（策略名 + JSON Statement 表单）。前端 JSON 语法校验 → eiam 服务端 schema 校验，失败标红。

## Reference Files
- docs/features/platform-console/ui/ui-design.md — 策略管理 UF-10：Layout/States（校验失败标红）/Interactions/Data Binding (ref: 策略管理)
- docs/features/platform-console/design/tech-design.md — C 档 policy 端点（Statement 数组、Effect Allow/Deny）、Policy/PolicyStatement 模型与归一规则 (ref: Interfaces / Data Models)

## Acceptance Criteria
- [ ] policyList store（统一契约）+ policies.ts api（list/create/update/delete）+ 写前守卫/回读接入
- [ ] 编辑 Dialog：策略名（1–64 唯一）+ Statement 数组表单（Effect∈{Allow,Deny}、actions/resources 非空数组、condition 可选）
- [ ] 前端 JSON 语法校验失败 → 错误字段标红 + 阻止保存；再 eiam 服务端 schema 校验（字段名/枚举/结构），任一失败标红对应字段
- [ ] 删除被拒（E11）：已绑定角色的策略删除提示绑定角色数并阻止（delete.blocked_policy）
- [ ] 仅平台管理员可见/可编辑（菜单 + 守卫双重口径，租户管理员与只读/审计入口不渲染）

## User Stories
Story 2（策略定义）、Story 4（创建策略定义绑定角色、租户管理员无策略定义入口）承接。

## Hard Rules
策略定义仅平台管理员可增删改（租户管理员/只读角色入口不渲染）；策略内容合法性 = 前端 JSON + eiam schema 双校验，任一失败阻止保存。

## Implementation Notes
- 仅新增：`src/views/policies/`、`src/stores/policyList.ts`、`src/api/policies.ts`。
- Policy 为 Statement[]；若实核 eiam 为扁平单 effect 结构则归一为恰含一条 Statement 的数组，多 Statement 无法表达时上报 validation 不静默截断（归一规则注释即在 2.3）。
