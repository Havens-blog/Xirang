# 5.5: M4 E2E：权限管理 CRUD + acceptance 全场景通过

## Description
真实浏览器验证权限管理三页（角色/授权/策略）CRUD 正向/负向/边界 + 越权 403 收敛 + E6 并发编辑 409。跑通全量 acceptance.md 场景（E1–E12 + UF-1~11 全过，负向+边界 ≥1/3），作为 M4 出口与 RC#1（5.4）前置门输入。

- docs/features/platform-console/prd/prd-spec.md — M4 出口判据（acceptance.md 全部场景通过；RC#1 前置门双签）、验收清单约束 (ref: Milestones)

## Acceptance Criteria
- [ ] 角色/授权/策略 CRUD 正向：创建角色绑定策略分配用户、三元组授权、策略 Statement 增删改查 → eiam 同步
- [ ] 越权负向：只读/租户管理员经 URL 直入越权页 → eiam 403 → 原地提示不跳转，数据不变（Story 3/5）
- [ ] E6 并发编辑：同一对象并发编辑 → 409（或降级并入 validation）→ save.conflict 提示 + 重新加载
- [ ] 全量 acceptance.md 场景 100% 通过（E1–E12 + UF-1~11 每条 ≥1，负向+边界 ≥1/3），逐条附 Playwright 用例链接
- [ ] Story 4 授权生效：分配后该用户下一次请求即具权限（逐请求判定，无需重登）；删除授权后请求被拒（生效延迟 ≤30s Phase 0 核查）

## User Stories
Story 3（越权 403）、Story 4（分配角色授权生效/删除失效）、Story 5（只读角色 403）承接。

## Hard Rules
验收宿主必为 nginx 同域形态；acceptance 场景必须逐条真实浏览器证据，不得 mock 会话或跳过负向/边界；全部通过是 5.4 RC#1 前置门输入之一。
