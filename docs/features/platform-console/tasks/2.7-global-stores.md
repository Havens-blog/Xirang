# 2.7: 全局 stores（user.ts + tenant.ts）

## Description
落地 2 个全局 store：`user.ts`（会话/profile/permissions/currentTenantId）+ `tenant.ts`（currentTenantId + 切换动作，租户上下文唯一归属）。fetch 前中断在途（AbortController），永不 persist。

## Reference Files
- docs/features/platform-console/design/tech-design.md — Store 清单（10 个）、职责边界（租户上下文唯一归属 tenant.ts、api 层零租户状态、persist 仅 theme） (ref: Architecture)
- docs/features/platform-console/design/tech-design.md — profile 端点 ProfileData 形状（user/permissions/tenants/current_tenant_id/is_admin/must_select_tenant） (ref: Interfaces)

## Acceptance Criteria
- [ ] user store：profile 拉取（GET /api/iam/user/profile 归一 ProfileData）、permissions、currentTenantId、isAdmin/mustSelectTenant
- [ ] tenant store：currentTenantId + 切换动作（调 tenant/switch 后整页 location.replace），租户上下文唯一归属于此
- [ ] fetch 前 AbortController 中断在途请求；profile 失败归位 error
- [ ] 两个 store 均不声明 persist（会话态不落 localStorage）

## User Stories
Story 1（登录后我的信息）、Story 3（租户边界）、Story 6（登出双侧失效）的会话/租户状态源。

## Hard Rules
租户上下文唯一归属 tenant.ts，api 层零租户状态；禁止任何 session store 声明 persist。

## Implementation Notes
- 仅新增：`src/stores/user.ts`、`src/stores/tenant.ts`。消费方：router 守卫（2.6）、主布局（2.8）、工作台（3.3）、租户选择（3.2）。
- must_select_tenant / 零租户 分流的判定源在此落地，供 3.2 分流逻辑使用。
