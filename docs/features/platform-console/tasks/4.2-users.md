# 4.2: 用户管理页（UF-4）：列表/搜索/编辑 + passkey 注册引导

## Description
落地 /users + 用户详情/编辑子页（/users/:id）：`userList` store + `users.ts` api（list/create/update/delete/reset_password/passkey 注册引导）。列表/搜索/角色过滤/分页（E7 边界）、新增 Dialog（初始密码展示一次）、编辑子页（角色绑定/租户组织关联/状态）、删除确认、passkey 注册引导（15 分钟一次性会话）与撤销重绑。

## Reference Files
- docs/features/platform-console/ui/ui-design.md — 用户管理 UF-4：Layout/States/Interactions/Data Binding、用户详情子页、passkey 注册引导与撤销重绑 (ref: 用户管理)
- docs/features/platform-console/design/tech-design.md — A 档 user 端点、C 档 reset_password/passkey register、User 模型 (ref: Interfaces / Data Models)

## Acceptance Criteria
- [ ] userList store（统一契约 state{items,total,page,pageSize,loading,error}+fetch/create/update/remove，AbortController 中断在途）+ users.ts 全部端点 + 写前守卫/响应回读（3.1）接入
- [ ] 列表/搜索/角色过滤/分页：page 超界回落最后页、删除末页唯一记录回退上一页、切过滤重置 page=1（E7）
- [ ] 新增：用户名格式（3–32，`^[a-z][a-z0-9_-]{2,31}$`）前端即时拦截 + 唯一性 eiam 反馈（E10）+ 初始密码（设置或生成）展示一次
- [ ] 编辑子页：用户名只读、登录方式、角色绑定多选、所属租户/组织关联、状态；保存返回列表 ≤2s 刷新
- [ ] 删除确认；依赖删除被拒（E11）弹窗列阻断计数、确认置灰（后续复用 delete.blocked 契约）
- [ ] passkey 注册引导：管理员发起生成一次性会话（15 分钟/单次），设备丢失重启流程 = 撤销原绑定 → 重新引导；passkey 唯一登录方式且回收走 reset_password（E1）

## User Stories
Story 2（平台用户 CRUD 同步、身份源/用户提交被拒字段标红）、Story 3（租户内过滤）、Story 4（分配角色）的用户侧承接。

## Hard Rules
初始密码仅展示一次（不在列表/编辑回显）；passkey 私钥仅存用户设备，控制台与 eiam 不代持、不导出；写前守卫不得绕过。

## Implementation Notes
- 仅新增：`src/views/users/`（列表 + 详情子页）、`src/stores/userList.ts`、`src/api/users.ts`。
- User 模型 orgRef/锁定态以 2.3 的「待核验」标注为准（Phase 0 回填）；reset_password/passkey register 端点形状为 C 档推定，Phase 0（1.1）核验后固化。
