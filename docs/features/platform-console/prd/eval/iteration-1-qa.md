1. **Problem → Solution**：问题（ecmdb-web 下线导致平台身份/权限/工作台 UI 断供）与方案（纯前端控制台直调 eiam + 共享 Redis session + 迁出 platform/users）对应成立。方案没有偷换成更简单的问题——它同时处理了登录、SSO 互通、双处维护消除和 401 跳转切换。

4. **自相矛盾检查 / SC 一致性深挖**：
   - **配对 satisfiability 检查（按影响面聚类）**：
     - In-Scope「工作台（纯 eiam 侧…）」↔ Out-of-Scope「工作台跨服务聚合」：兼容（子功能拆分，非互斥）。

## Phase 3 — Blindspot Hunt（rubric 未覆盖的问题）

1. **[blindspot] 目标指标无分母，不可作发布门禁** — "真实浏览器（Playwright/浏览器 MCP）验证通过率 100%" — 全文未定义该百分比覆盖的验收场景清单（多少条、哪些路径、含哪些负向用例）。QA 无法把 "100%" 变成可执行的 pass/fail 门禁。必须改进：枚举 SSO/登录验收场景清单（正向 + 负向 + 边界），或在文档中指明清单产出的宿主与完成形态。
2. **[blindspot] 迁移前置门无可验证证据形态** — "前置门：控制台对 Phase 0 清单逐项覆盖完成；附引用盘点/回归/回退" — Phase 0 清单本身是本项目产物，"逐项覆盖完成" 未定义证据形式（核验单 artifact？谁签收？）。下游 agent 无法判定门禁何时通过。必须改进：定义清单交付物形态与验收签认方式（如 parity checklist 文件 + 逐项 evidence 链接）。
3. **[blindspot] 自证式 Quality Checklist 与实情冲突（文档完整性）** — "- [x] 表格填写完整、无可疑含糊措辞" 及 "- [x] 流程描述完整 + Mermaid 图含决策点与异常分支" — 本次评审证实两处均不完全成立（"策略内容合法性校验"/"活跃用户" 含糊；MFA 失败分支缺失、403 分支错路由）。Reasoning audit flagged this independently of dimension scoring：自我勾选且无 evidence 的质量清单制造虚假置信。必须改进：改为带证据链接的核验项，或删除自评勾选。
