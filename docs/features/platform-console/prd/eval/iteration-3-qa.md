## Phase 3 — Blindspot Hunt（rubric 未覆盖的问题）

1. **[blindspot] 过渡期三方登出语义在验收映射矩阵中无映射来源** — 「任一侧（控制台/e-cam-web；过渡期含 ecmdb-web）登出即销毁共享 session，其余应用/标签页在下一次请求时 401 收敛并跳回控制台登录页」+「映射矩阵：E1–E12 每条至少 1 个验收场景，UF-1–UF-11 每个 UF 至少 1 条」 — 映射矩阵的来源枚举是 E1–E12 ∪ UF-1–11，而过渡期 ecmdb-web 的 401 收敛/登录入口重定向（「权威登录入口 = 控制台 /login，ecmdb-web 登录入口重定向至此」）既不是任何 E# 也不是任何 UF#——按当前矩阵约束，该 launch 阻断级行为**结构性不可被任何验收场景覆盖**，M2 出口判据「单点跳转与双侧登出（Story 6）通过」也只测双侧。Reasoning audit 的 Evidence→Success Criteria 环节独立发现，维度 1 已高分、无维度承载此缺口。必须改进：将过渡期三方场景登记为映射源（如新增 E13 或在验收约束中显式增加「过渡期三方语义至少 1 条场景」）。

2. **[blindspot] 强制改密流程的验收不可构建性（与 CONTRADICTION-2 同源的门禁视角）** — 「M1 \| … \| 登录正/负/边界场景（E1/E2/E8/E9）真实浏览器通过」 — E1 场景的终态断言「该用户首次登录强制改密」需要用户侧改密界面才能执行，而该界面在 11 个 UF 与登录页 States 中均不存在，且 Out of Scope 将「eiam 侧既有自助端点如存在，其 UI 承载不属本提案」——即验收门要求通过一个 PRD 未指派任何交付方的 UI 流程。Reasoning audit flagged this independently of dimension scoring（维度 3 已按矛盾计 -30，此处为里程碑门禁层面的独立后果）。必须改进：同 CONTRADICTION-2 的三选一处置，并确认 M1 出口判据在处置后可执行（或将 E1 移至 UF-4 交付的 M3/M4 出口判据）。
