## Phase 1 — Reasoning Audit（独立推理审计）

**Problem → Solution 链条**：问题（ecmdb-web 下线 → 平台身份/权限/工作台 UI 断供 + 依赖他人前端违背「100% 可控」）→ 方案（新建纯前端控制台直调 eiam 已有 API，复用共享 Redis session）。方案确实回应问题，且「零新增后端」与「复用 eiam」自洽。但方案成立的前提（eiam 现有端点足以支撑 parity）未被断言为事实，而是被显式降级为 Phase 0 待核查 + 三类处置决策门（`缺口三类处置（UI 降级仅查看类 / 扩端点需显式决策 / 放弃需业务确认）`）——这是好的风险显性化，但引出下述矛盾 a。

**发现的独立问题（pre-score anchors）**：

a. **Parity 指标与处置决策门互相矛盾**：Goal 1 要求 `Phase 0 parity 清单 100% 覆盖`，而 Related Change 3 允许缺口「放弃需业务确认」。若任一缺口被处置为「放弃」，100% 覆盖在数学上不可达；PRD 未定义「放弃后是否从 parity 清单剔除/指标是否重算」。推导：满足「放弃某缺口」 ⇒ parity < 100% ⇒ Goal 1 失败；满足 Goal 1 ⇒ 不存在被放弃的缺口 ⇒ Change 3 的第三类处置形同虚设。双向至少一个方向失败。

b. **租户管理员 × 策略权限三方冲突**：Background 用户表 `管本租户用户/角色/授权，不可超出租户边界`（无策略）；Story 3 `管理本租户内的用户/角色/授权`（无策略）；Story 4 `**As a** 平台管理员或租户管理员 … 创建角色、绑定授权/策略并分配给用户`（含策略）；UI 导航规则 `租户管理员见 2/6/7/8（租户内）`，其中 8 = 策略管理（含策略）。四处两两不一致。

c. **DF002 预先断言了待核查事实**：Flow step 3 说 `tenant_id 写入共享 session 口径以 Phase 0 事实核查为准`，但 DF002 已写死 `会话写入（JWT claims：uid/username/tenant_id）`。属「以 Phase 0 为准」的暂定口径，可接受，但表格未标注 provisional，存在被下游当作既定事实的风险。

d. **会话三方问题**：架构上 ecmdb-web（过渡期仍在线）、控制台、e-cam-web 三端共享同一 eiam session；单点登出只定义了控制台↔e-cam-web 双向，ecmdb-web 侧未被纳入。

e. **正向验证**：背景证据具体可核（`现有 29 个 proposals 无任何门户/控制台/身份治理相关条目`、具体视图路径）；多标签页 `靠下次请求 401 统一收敛，不做实时广播` 是诚实且可实现的设计取舍；迁移项带 `前置门` + `引用盘点/回归/回退`。这些是真实优点，评分时不得因其存在而无视 a/b。

## Phase 3 — Blindspot Hunt

**[blindspot] 1 — 授权执行层（server-side enforcement）从未被声明为需求。**
这是权限管理控制台的 PRD，但全文关于权限的表达都是 UI 层的：`越权菜单不渲染；无权限操作明确提示`、`仅平台管理员可见`、`可见范围按角色裁剪`。前端裁剪只是展示控制；「直调 eiam 已有 API」意味着 API 是否服务端强制鉴权完全取决于 eiam 现状，PRD 既未声明该前提、也未把它列为 Phase 0 核查项（Phase 0 清单是端点差集 + 认证链路矩阵，不含授权执行矩阵）。S3 的 AC `发起越权请求 → 明确提示无权限，拒绝执行` 隐含了服务端拒绝，但作为需求从未成立。对身份/权限产品，这是产品级需求缺失而非实现细节。Reasoning audit 未单列此条，评分中 D6「无权限」给了部分分，但「enforcement 归属」不属于任何 rubric 维度，故以 blindspot 提出。必须改进：把「eiam 服务端对全部 CRUD 端点强制鉴权（前端裁剪仅为体验层）」写成显式需求并纳入 Phase 0 核查矩阵。

**[blindspot] 2 — 三端共享 session 的过渡期语义未定义。**
`任一侧登出，另一侧会话在下一次请求时失效并跳回控制台登录页`——「另一侧」预设了世界只有两侧。过渡期内 ecmdb-web 仍在线且同样直调 eiam：从 ecmdb-web 登出是否使控制台/e-cam-web 失效？ecmdb-web 登录写的 session 控制台是否承认？迁移期间两个登录页并存，哪个是权威入口？回切开关覆盖了运维回退，但没覆盖这三问。必须改进：在 Flow Description 或 Phase 0 兼容矩阵中显式加入 ecmdb-web 第三端的登出/登录互通语义与并存期权威入口声明。
