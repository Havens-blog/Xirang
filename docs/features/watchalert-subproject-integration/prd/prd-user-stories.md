# User Stories: WatchAlert 子项目并入（含 eiam 统一鉴权）

## Story 1: 运维工程师用平台账号登录告警平台

**As a** 运维/值班工程师
**I want to** 用平台统一账号（eiam）登录告警平台，而不是维护一套独立的 WatchAlert 账号
**So that** 一处账号即登录、审计统一到平台，减少账号维护负担

**Acceptance Criteria:**
- Given 我访问告警平台且未登录
- When 我被引导至 eiam 登录并完成认证
- Then 认证成功后我进入告警看板，并能按 WatchAlert 内部角色使用相应功能
- Given 我访问告警平台且未登录，eiam 认证返回失败
- When 我完成登录流程
- Then 回跳登录页展示错误信息（统一文案，不泄露用户名是否存在），可重试
- Given 我访问告警平台且未登录，eiam 服务不可用
- When 我尝试登录
- Then 直接进入只读免登录视图，提示等待鉴权服务恢复，不提供本地登录入口
- Given 我认证通过但无 WatchAlert 内部角色（未在 `watchalert_role_binding` 预置）
- When 我尝试访问告警平台
- Then 返回 403 原地提示「无访问权限，请联系管理员配置角色」，保持当前页不跳登录页（BIZ-auth-003）
- Given 我已登录并在使用中，会话过期
- When 我发起下一次请求
- Then 后端返回 401，前端跳转 eiam 登录页（不白屏、不无限 loading），重登成功后回原操作路径（BIZ-auth-008）

## Story 2: 运维工程师在鉴权服务不可用时仍能查看告警

**As a** 运维/值班工程师
**I want to** 在平台鉴权服务（eiam）不可用时仍能看到告警现状
**So that** 鉴权单点故障不会让我完全无法了解告警态势

**Acceptance Criteria:**
- Given 我已登录且持有会话
- When eiam 变不可用
- Then 页面顶部显示「鉴权暂不可用」宽限横幅，宽限期（2 小时）内我可只读查看、写操作返回 503 且前端提示不可写；宽限期过后降级为只读免登录视图
- And 未登录用户此时也直接进入只读免登录视图，且不提供任何本地登录入口

---

## Story 3: 旧本地账号彻底失效

**As a** 告警平台管理员
**I want to** 确认 WatchAlert 的旧本地登录入口已彻底移除
**So that** 不存在绕过 eiam 直接拿 token 的后门，SSO 真正生效

**Acceptance Criteria:**
- Given 我使用旧的用户名/密码
- When 直接请求已移除的登录接口
- Then 接口返回 404 且不签发 token（端点已移除语义；401 仅用于未认证，不用于已移除端点）
- And 前端无本地登录入口残留

---

## Story 4: 平台开发者一键启动与验证告警子系统

**As a** 平台开发者
**I want to** 用平台统一命令一键启动告警子系统的后端与前端，并能跑统一质量门禁
**So that** 不用再跨两个独立目录手动编译/启动，告警子系统像其它子项目一样被管理

**Acceptance Criteria:**
- Given 我执行统一启动命令
- When 后端编译成功
- Then 后端(:9001) + 前端(:3001) 被拉起，状态/日志可查
- And 后端编译失败时状态给出显著标记（区别于普通业务服务静默续跑）
- And 统一质量门禁可触发编译/格式化/静态检查/单元测试且通过

---

## Story 5: 运维工程师登出后全标签页会话失效

**As a** 运维/值班工程师
**I want to** 在告警平台登出后，所有打开的告警平台标签页会话同步失效
**So that** 在公共/值班机登出不会遗留可用会话，避免他人借机操作

**Acceptance Criteria:**
- Given 我在告警平台任一标签页登出
- When 登出请求完成
- Then 共享会话被销毁（WatchAlert 复用平台共享会话，不自建独立会话存储、不签发进程内自签名会话票）
- And 其余标签页下次请求时后端验会话查不到共享存储记录返回 401，前端收敛跳转 eiam 登录页（不做实时广播，不引入 WebSocket/BroadcastChannel）（BIZ-auth-005）

---

## Story 6: 运维管理员执行迁移切流并验证告警不丢

**As a** 告警平台管理员
**I want to** 将生产流量从旧 WatchAlert 实例切流到新实例，并验证告警全链路不丢
**So that** 迁移不导致告警遗漏/重复/通知丢失，且可安全回滚

**Acceptance Criteria:**
- Given 新旧实例并行运行且新实例不接生产流量
- When 配置迁移完成（告警规则/数据源/通知配置导出导入）
- Then 配置条数对齐（旧=N，新=N，diff=0）且抽样规则触发验证一致，方可进入切流。抽样口径：样本量 = max（≥ 10% 规则总数，≥ 50 条），抽样方法 = 随机抽取覆盖各规则级别（P0/P1/P2）与各数据源类型的规则；「一致」定义 = 同一规则用相同输入触发，新旧实例告警产出时间差 ≤ 5 秒且告警内容（级别/标题/接收人）字段完全相同
- Given 配置导入过程中部分条目失败（如某条规则格式不兼容或数据源连接异常）
- When 导入工具报告部分失败
- Then 导入中止当前批次，已成功导入的条目保留并标记为「待确认」，失败条目输出错误清单（含失败原因）；管理员可选择修复后重导失败条目（增量导入，不重复已成功条目）或回滚至并行阶段（清空新实例已导入配置后重导全量）；不进入切流阶段直至全量 diff=0
- When 反代灰度切流（先 10% 流量观察 15 分钟无 5xx/鉴权失败激增，再 100% 切流）
- Then 鉴权成功率 ≥ 99.9%、告警延迟 P95 ≤ 300ms
- When 观察一个完整告警周期（15 分钟，覆盖告警评估→通知全链路）
- Then 无告警遗漏/重复/通知丢失，方可进入退役阶段（旧实例保留只读两周后下线）
- Given 切流后任一阶段 fail 或监控告警（鉴权成功率 < 99%、5xx 率 > 1%）
- When 触发回滚
- Then 反代回切旧实例（≤ 2 分钟完成），新实例转只读排查，配置以旧实例为准，数据一致性靠旧实例仍为主源保证
- And 若反代回切本身失败（控制面不可达或回切超 > 2 分钟），执行手动 DNS 切换指回旧实例 VIP；切换期间双实例并存均设只读（写操作 503），避免双写不一致；DNS 切换完成后人工确认旧实例全量承载再解除只读
