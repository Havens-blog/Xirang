# Proposal: WAF 流量诊断(网站被刷检测)

## Problem

运维/安全需要快速判断**网站是否被恶意刷量**(CC 刷量 / 恶意爬虫 / 接口爆破),以及**流量来源**与**处置措施**;当前日志查询只有原始聚合(Total / TopN / 趋势),没有"被刷判定 / 来源归因 / 措施建议"的结论性输出,判断完全依赖人工经验。

### Evidence

- 日志查询页已能查 WAF 全窗聚合(分桶 / TopN / 总条数),但"有没有被刷"需人工看趋势 + Top 域名逐项判断,无法一键得出结论。
- 阿里 WAF 近 6h 全窗 8000 万行量级(实测),人工从明细定位攻击源不可行;SLS 按扫描量计费,反复人工查全窗成本高。
- 被刷典型特征(单 IP 高频、UA 异常、请求突增、攻击动作占比高)是**确定性可计算的**;现有聚合维度(client_ip / user_agent / 状态码 / 动作)已具备数据基础(实测 aliyun aggregatable 含 client_ip/user_agent)。

### Urgency

- 被刷是持续威胁,发现滞后 = 带宽 / 费用 / 业务可用性损失(如刷量耗尽 CDN 回源带宽)。
- 延迟成本低(可先手动触发),但每次人工判断需多次查询才能拼出结论——一次结构化的诊断输出是直接改进。

## Proposed Solution

在日志查询 **WAF Tab 内嵌"流量诊断"卡**(手动触发):后端对**当前窗口 + 前一等长窗口**做聚合(复用现有联邦聚合通道,新增一次前窗对比查询),规则引擎输出 **风险等级 / 疑似攻击类型 / Top 攻击源 IP / 来源分布 / 措施建议**。AI 总结接口**后置**(响应预留 summary 字段,模型接入后填充)。

### Innovation Highlights

- **判据可计算**:把"有没有被刷"从经验判断变为可复现的规则评分(单 IP 最高频率 + 前窗突增倍数 + UA 异常 + 5xx/攻击动作占比)。
- **复用现有数据面**:不新增日志采集/存储,全部走既有 `/aggregate` 通道(分桶 + TopN),前窗对比仅多一帧聚合。
- **前窗对比是关键判据**:突增倍数区分"常态流量"与"突袭",是大促误报与真被刷的分界。
- **措施由规则映射**:封禁 Top 攻击源 / 开启 CC 防护 / 限流 / UA 黑名单,零云侧操作风险。

## Requirements Analysis

### Key Scenarios

- **正常低流量**:Total 低、无突增、UA 分布正常 → 风险等级"无/低",无攻击源。
- **CC 刷量**:单 IP 请求频率极高 + 前窗突增 → 判定 CC,Top 攻击源为高频 IP。
- **恶意爬虫**:UA 异常/单一 + 高请求数 + 4xx 占比高 → 判定爬虫,措施含 UA 黑名单。
- **接口爆破**:单 IP 高频打少数 URI + 4xx 高 → 判定爆破,措施含限流/封禁。
- **大促正常高流量**:突增但 UA 分布多样、来源地理分散、无攻击动作 → 低风险(避免误报)。
- **错误场景**:部分源聚合失败 → per-source 状态标注,已聚合源照常判定;前窗无数据 → 突增判据缺失,降级为仅当前窗绝对量判定。

### Non-Functional Requirements

- 诊断一次 ≤ 2 次聚合查询(SLS 扫描计费:当前窗 + 前窗),手动触发成本可控。
- 规则引擎为纯函数(输入聚合行 → 输出判定),单测覆盖率 ≥ 80%。
- 响应携带 per-source 状态与 `summary` 占位字段(AI 解读后置接口)。

### Constraints & Dependencies

- 依赖现有 `/aggregate` 联邦能力(client_ip / user_agent 维度 TopN + 分桶),不新增大数据组件。
- 当前唯一有 WAF 数据的云为阿里(AWS 无聚合、华为 WAF 非结构化、腾讯 WAF 未投递);诊断基于阿里 WAF,其他云 WAF 接入后沿用同一规则引擎。
- SLS 按扫描量计费:前窗对比多一帧扫描,必须手动触发而非随查询自动。

## Alternatives & Industry Benchmarking

### Industry Solutions

- **WAF 厂商自带**(阿里云 WAF 控制台 / Cloudflare):产品内建 CC/爬虫防护与报表,但结论在云控制台,与自建日志查询隔离;且需开启对应防护能力。
- **开源规则引擎 / 异常检测**(如 Elasticsearch 阈值告警、时序突增检测):与本方案同思路,但需自建数据管线。
- **LLM 端到端分析**:把日志统计喂给大模型生成判断,灵活但不可审计、有延迟/成本、结论不稳定。

### Comparison Table

| Approach | Source | Pros | Cons | Verdict |
|----------|--------|------|------|---------|
| Do nothing(人工看聚合) | — | 零开发 | 依赖经验、慢、每次多查询多计费 | Rejected: 无法规模化判断 |
| 云厂商 WAF 控制台报表 | 阿里云 WAF | 权威、含防护 | 与自建日志查询隔离、只覆盖该云、需开防护 | Rejected: 不符合统一日志平台 |
| 端到端 LLM 分析 | 大模型 API | 灵活、自然语言 | 不可审计、延迟/成本、判断不稳定 | Rejected: 不适合作为安全判断唯一依据 |
| **规则为主 + 可选 AI 解读** | 本项目方案 | 可复现/可审计/零外部依赖,复用现有聚合;AI 仅作可选的报告解读 | 规则阈值需校准 | **Selected: 判据确定可靠,AI 解读接口后置** |

## Feasibility Assessment

### Technical Feasibility

现有聚合通道(client_ip / user_agent TopN、分桶、Total)已在生产可用;新增 `POST /logs/diagnose` 接口 + 规则纯函数 + 前端诊断卡,无 showstopper 技术依赖。

### Resource & Timeline

团队熟悉现有联邦聚合/前端日志页架构;规则引擎为纯函数可快速单测;估 1-2 天(后端接口 + 规则 + 前端卡)。

### Dependency Readiness

阿里 WAF 数据流动正常(实测近 7 天持续写入);client_ip / user_agent 维度可聚合(实测在 aggregatable 白名单内)。无上游阻塞。

## Assumptions Challenged

| Assumption | Challenge Tool | Finding |
|------------|---------------|---------|
| "判断被刷需要引入 AI" | 5 Whys / Occam's Razor | Overturned: 被刷特征可计算,规则优先;AI 仅作可选的报告解读。用户确认"规则为主 + AI 后置" |
| "智能分析需要独立页面" | Need Gate | Refined: 内嵌 WAF Tab 复用现有聚合上下文、改造成本低。用户确认内嵌 |
| "查询后自动诊断" | Need Gate(成本) | Overturned: 每查询多一帧聚合、SLS 计费翻倍。用户确认手动触发 + 前窗对比 |

## Scope

### In Scope

- 后端诊断接口 `POST /logs/diagnose`:当前窗聚合(Total / 分桶 / Top client_ip / Top UA / 状态码 / 动作分布)+ 前窗对比(Total 与 Top IP 突增倍数)。
- 规则引擎(纯函数、可单测):风险分 = 单 IP 最高频率 + 突增倍数 + UA 异常 + 5xx/攻击动作占比 → 风险等级(无/低/中/高)+ 疑似攻击类型(CC 刷量 / 恶意爬虫 / 接口爆破 / 正常高流量)。
- 措施映射:规则 → 具体文案(封禁 Top 攻击源 IP、开 CC 防护、限流、UA 黑名单)。
- 前端:WAF Tab 内嵌"流量诊断"卡(触发按钮、判定结论、来源 Top、趋势对比、措施清单)。
- 响应预留 `summary` 字段(AI 解读后置接口)。

### Out of Scope

- 云侧操作(封禁 / 限流)——只给建议文案,不碰云 API。
- AI 总结生成——接口后置,模型接入另行立项。
- 独立安全分析页面 / 多窗口历史趋势(只对比前一等长窗口)。
- SLB / CDN 类型诊断(规则引擎结构可复用,本期仅 WAF)。
- 华为 / 腾讯 WAF 诊断(数据源未流动,接入后沿用规则引擎)。

## Key Risks

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|------------|
| 前窗对比误报(大促高流量被误判被刷) | M | M | UA 正常性 / 来源地理分散度加权降分;等级阈值配置化,先按实测校准 |
| 规则阈值不通用(不同站点基线差异) | M | M | 阈值集中配置(可调),首版按阿里 WAF 实测数据锚定 |
| 前窗对比多一帧 SLS 扫描计费 | H | L | 手动触发,单次仅 +1 帧;响应标注成本 |
| 部分源聚合失败 / 前窗无数据 | M | M | per-source 状态标注,已聚合源照常判定;突增判据缺失降级为绝对量判定 |
| 单 IP 维度 TopN 在某 store 不索引 | L | M | 走现有 passthrough + indexHint;不可聚合 store 单独标注 |

## Success Criteria

- [ ] WAF Tab 出现"流量诊断"入口,手动触发后 ≤ 2 次聚合查询返回诊断结果。
- [ ] 诊断结果包含:风险等级(无/低/中/高)、疑似攻击类型(≥3 类可判)、Top 5 攻击源 IP(含请求数与占比)、来源分布(Top 地域)、≥3 条措施文案。
- [ ] 规则引擎纯函数单测覆盖:风险分计算、等级边界、攻击类型判定、措施映射;覆盖率 ≥ 80%。
- [ ] 前窗无数据 / 部分源失败时诊断不报错,返回降级标注;明细/聚合既有行为回归通过。
- [ ] 响应预留 `summary` 字段(空串,AI 解读后置)。
