# Proposal: CDN 缓存分析(命中率与缓存优化)

## Problem

运维/优化需要快速回答 **CDN 缓存健康度**:当前命中率多高(请求 / 字节)、哪些**域名 / URI** 缓存失效最重、**回源流量浪费**多少、该怎么做缓存优化;当前日志查询只有原始聚合(Total / TopN / 趋势),没有"命中率判定 / 未命中定位 / 优化建议"的结论性输出,优化依赖人工逐域名 / 逐 URI 排查。

### Evidence

- CDN 统一模型已含 `cache_hit`(hit/miss/partial/error)与 `bytes_sent`,`/aggregate` 已支持 `cache_hit` 维度与 `sum_bytes` 指标;已覆盖源含 aliyun DCDN(hit_info 聚合白名单实测)、Akamai(cacheStatus 已归一)、离线转存(HitInfo 已归一)、EdgeOne(EdgeCacheStatus→cache_hit 归一映射 + 聚合维度,见 tencent/eo.go)——**数据面零新增采集**。- 线上实测(2026-09-20):CDN aliyun 1h 全窗 **1453 万请求**,域名 datasink.jlc.com 单域名 **286 万次**;www.jlc-smt.com 等 WAF 站点 2.2M/h —— 域名/URI 级缓存失效面大,人工逐项看成本高。当前命中率基线可得:`/aggregate` 已支持 `cache_hit` 维度,可先行用其出按域名的请求命中率基线,先量化"当前命中率/未命中流量";"可缓存口径 / 字节口径"基线依赖本期规则引擎,交付后再校准;金额以未命中流量估算为主、不夸大。- 请求命中率与字节命中率的差距直接对应**回源带宽 / 流量费用浪费**(大文件未命中 = 高字节回源);金额量化分两级(未命中流量估算 → 有回源单价后换算金额,假设显式),是 CDN 优化最实的抓手。### Urgency

- 缓存优化是持续成本项:命中率每低 1 个点,热点域名的回源带宽/流量费都会放大;延迟 = 费用 + 源站压力双损失。
- 现有功能已具备全部数据基础,缺的是一次"结论性 + 可执行"的结构化分析;做出来即日可用(手动触发,成本可控)。

## Proposed Solution

在日志查询 **CDN Tab 内嵌「缓存分析」卡**(手动触发,镜像 WAF 流量诊断卡交互):后端对**当前窗口 + 前一等长窗口**做聚合(复用现有联邦聚合通道),规则引擎输出 **请求命中率 + 字节命中率(全请求/可缓存双口径,定义见 Innovation)、域名命中率排行、未命中 URI TOP、状态码分布、结构化缓存优化项(域名/URI 前缀 + 建议动作 + 未命中流量占比)**;AI 解读**后置**(复用已落地的 `llm` 包,env 开启才调,失败降级;**外发仅限聚合统计,URI 级数据外发前剥离 query 参数与 PII,只发查询串归一后的路径与统计数值,不发原始日志/请求明细**)。### Innovation Highlights

- **双命中率口径(全请求/可缓存两档)**:请求命中率分别按全请求与可缓存请求计算,档位与优化项基于可缓存口径。**可缓存口径的剔除判据基于聚合层可得字段的近似**:按 `cache_hit×status` 剔除 4xx/5xx 与 `cache_hit=error`,按 ×uri 维度的常见动态路径后缀启发式仅作提示;method(POST)/认证/Range 不在单维度 `/aggregate` 输入中,无法剔除,一律计入可缓存分母并显式标注"可缓存档为聚合层近似(口径偏保守,避免高估命中)"。**字节命中率(双口径)**:全请求字节命中率 = hit+partial 字节 / 总字节(主口径,partial 按全命中计入并标注"字节命中率上偏",可折算分片命中字节时再折算)+ 可缓存字节命中率(可缓存请求的 hit+partial 字节 / 可缓存请求总字节,与可缓存请求档对齐);两者 gap 大 = 大文件未命中 = 回源带宽浪费;金额量化分两级(未命中流量估算 → 有回源单价后换算金额,假设显式)。- **未命中归因到 URI 前缀**:URI 聚合先对查询串做归一(剥离/排序 query 参数),避免同一资源带不同参数被拆散稀释 miss 集中度;URI 级 miss 集中度是缓存规则优化的直接输入,优化项**结构化**(域名 + URI 前缀 + 建议动作:加缓存规则 / 调 TTL / 忽略查询串 / 强制回源校验),可执行而非纯文案;"忽略查询串"动作须附 miss 集中证据。- **复用 WAF 诊断骨架**:聚合并发通道 / 前窗对比 / SWR 缓存 / per-source 降级 / AI 后置全套复用,交互一致、成本可控(一次分析 ≤ 2 帧聚合)。
- **缺失源降级**:尚未映射 cache_hit 索引的源(EdgeOne 已映射,不含在内)显式标注(dimension_notes 风格),已覆盖源照常计算,不白屏。## Requirements Analysis

### Key Scenarios

- **缓存健康**:可缓存请求命中率 ≥ 优档阈值(默认 90%,参数化)且字节命中率接近 → "优",无优化项或少量提示。档位边界初始化:上线初期按各域名**历史命中率分位数**初始化——历史数据来源为一次性查询现有 `/aggregate` 按域名分组的历史 cache_hit 聚合(不新增采集/存储),取不到时回退默认阈值;**漂移监控不属本期**:周期性漂移看护归入定时看护(diagwatch)后续立项,本期仅提供单次快照 + 档位参数化,不做周期巡检;动态占比高域名阈值按历史分布校准,避免不可达。- **未命中集中**:某 URI 前缀 miss 占比高(如动态接口误开缓存 / 查询串不忽略)→ 优化项:该前缀加/调缓存规则、忽略查询参数。
- **大文件未命中**:请求命中率 OK 但字节命中率明显低(gap 大)→ 大文件回源带宽浪费,优化项指向大文件 URI + TTL/分片建议。- **小文件未命中(请求方向)**:字节命中率尚可但请求命中率低(小文件大量 miss)→ 回源请求数 / QPS 与按请求计费的浪费,优化项指向小文件 URI + 缓存规则 / 预缓存建议;请求与字节两个方向的 gap 归因同时纳入优化项。- **4xx/5xx 高**:状态码口径**默认交付为当前窗状态码分布单独展示**(4xx/5xx 占总响应占比,单维度 ×status 可得);"命中(hit)响应里 4xx/5xx 占比"需"状态 × cache_hit"二维交叉,单维度 /aggregate 做不到,列为**后续增强、本期不承诺**;4xx/5xx 占比高 → 缓存对错误响应无效,建议回源校验/缓存规则排除错误码。- **前窗对比**:对比基期默认前一等长窗口(卡面标注"对比基期:前一 N 分钟"),命中率较基期上升 / 下降,标注趋势(↑↓),下降 > 阈值时提示关注;部分源前窗失败时,趋势 ↑↓ 标注"基于 X/Y 源"并列出缺失源,避免部分覆盖被读成全量;后续可加同时段昨日/上周同比。- **错误场景**:尚未映射 cache_hit 索引的源(EdgeOne 已映射,未来新源)→ 命中率按已覆盖源计算并标注覆盖范围;前窗无数据 → 只给当前窗绝对量判定;单源聚合失败 → per-source 状态标注。### Non-Functional Requirements

- 一次分析 ≤ 2 帧窗口聚合(当前窗 N 次维度聚合 + 前窗 1 帧),手动触发控制 SLS 扫描成本;**当前窗维度聚合次数 N 有上限(N ≤ 5**,即 host/uri/status/字节口径/前窗对比等维度组);窗口时长上限(最长 24h);执行前预估扫描量,预估超过 N 上限或扫描量阈值时**默认拦截并提示用户确认**,确认后才放行。- 规则引擎为纯函数(输入聚合行 → 输出判定 + 结构化优化项),单测覆盖率 ≥ 80%。
- 命中率口径与 `cache_hit` 分布聚合**可复现**(同一时间边界 + 尽量同一执行批次并发查询,避免 SLS 日志延迟导致各维度快照不一致;可复现断言限定于此),partial/error 归类文档化。- 响应携带 per-source 状态与 `summary` 占位字段(AI 解读后置);前端卡交互镜像 WAF 诊断卡。
- **AI 外发隐私**:外发仅限聚合统计(域名/URI 前缀命中率、优化项、占比数值);URI 级聚合含查询串时,外发前剥离 query 参数与可能的 PII,只发查询串归一后的路径与统计数值,不发原始日志/请求明细;外发由 env 开关控制、失败降级。- **开关与回滚(灰度)**:新端点独立 feature flag(默认关);实现只新增、不改既有日志查询代码路径,失败时前端卡降级隐藏、不影响既有查询;灰度顺序为内部环境验证 → 放开手动触发入口 → 全量,异常时关闭开关即回滚。### Constraints & Dependencies

- 依赖现有 `/aggregate` 联邦能力(cache_hit 维度 + sum_bytes 指标 + 分桶),不新增采集/存储。
- 各源 cache_hit 语义差异(Akamai cacheStatus、DCDN hit_info、离线转存 HitInfo、EdgeOne EdgeCacheStatus 均已有映射)→ "原始组名→枚举"归一抽成与明细层共用的单一映射源(单源化),聚合层不再另走独立归一路径,补跨源/跨层对照测试;golden 回放(固定日志样本)锁定窗口口径一致。- SLS 按扫描量计费:必须手动触发而非随查询自动(与 WAF 诊断同约束)。

## Alternatives & Industry Benchmarking

### Industry Solutions

- **云厂商 CDN 控制台命中率报表**(阿里云 CDN / Akamai 报表):权威但只在各自控制台、按域名/报表粒度,与自建统一日志查询隔离,无法跨云横向比。
- **开源时序异常/命中率监控**(Grafana + 云指标):能看趋势但不下沉到 URI 级未命中归因,不产出可执行优化项。
- **纯 LLM 分析**:喂统计给大模型生成结论,灵活但不可审计、成本/延迟、结论不稳定,不适合作为优化依据唯一来源。

### Comparison Table

| Approach | Source | Pros | Cons | Verdict |
|----------|--------|------|------|---------|
| Do nothing(人工看聚合) | — | 零开发 | 依赖经验、慢、每次多查询多计费 | Rejected: 无法规模化定位未命中与优化 |
| 云厂商控制台命中率报表 | 阿里云 CDN / Akamai | 权威 | 跨云割裂、不下沉 URI、只该云 | Rejected: 不符合统一日志平台 |
| 纯 LLM 分析 | 大模型 API | 灵活、自然语言 | 不可审计、成本/延迟、结论不稳定 | Rejected: 不适合作为优化依据唯一来源 |
| **规则为主 + 可选 AI 解读 + 结构化优化项** | 本项目方案(复用 WAF 诊断骨架) | 可复现/可审计/零新采集,URI 级可执行建议,跨云统一 | 规则阈值需校准 | **Selected: 判据确定可靠,AI 解读后置** |

## Feasibility Assessment

### Technical Feasibility

现有聚合通道(cache_hit 维度、sum_bytes、分桶)已在生产可用(实测 aliyun DCDN cache_hit/sum_bytes 可聚合);新增 `POST /logs/cache-analyze`(复用 diagnose 编排骨架)+ 纯函数规则引擎 + 前端卡,无 showstopper 依赖。

### Resource & Timeline

团队已完整实现并验证 WAF 诊断同构功能(规则引擎/聚合并发/前窗对比/前端卡/AI 后置);但本期交付面大于纯同构(可缓存口径分类启发式、字节双口径、状态码口径、URI TOP 降级、前端新卡、跨源口径验证与回归测试),按交付面复核调整为 **2-3 天**:约 1 天新端点 + 规则引擎纯函数与单测、0.5-1 天前端卡、0.5-1 天跨源口径对照与回归。### Dependency Readiness

CDN 数据流动正常(实测 CDN aliyun 1h 1453 万请求);cache_hit 聚合白名单已覆盖 DCDN/Akamai/离线转存/EdgeOne(EdgeCacheStatus 归一映射 + 聚合维度,见 tencent/eo.go);无上游阻塞。## Assumptions Challenged

## Scope

### In Scope

- 后端缓存分析接口 `POST /logs/cache-analyze`:当前窗并发聚合 cache_hit×host(域名)、×uri(查询串归一后的 URI 未命中,单维度聚合、不做 host×uri 交叉)、×status(状态码分布,4xx/5xx 占比;状态×cache_hit 二维交叉为后续增强)+ sum_bytes(全请求与可缓存双字节口径)+ 前窗 1 帧(cache_hit 分布对比)。- 规则引擎 cdn-cache(纯函数、可单测):双命中率计算(全请求/可缓存两档)、健康档位(优/中/差)、请求-字节 gap(大文件回源带宽 + 小文件回源请求双向归因)、未命中 URI 集中度(查询串归一后)、4xx/5xx 占比 → **结构化优化项(非优档按未命中流量占比降序 Top N,默认 5;优档允许 0 条)**(域名/URI 前缀 + 建议动作 + 未命中流量占比);优化项带**可信度分级**(高 = URI miss 集中度与 gap 证据充分、中 = 启发式/近似口径、低 = 动态接口类启发式判定),卡面统一注明"**建议,执行前请验证**",仅供人工参考、不自动生效。- 前端:CDN Tab 内嵌"缓存分析"卡(折叠/手动触发/前窗对比/双命中率总览/域名排行/未命中 URI/状态码命中率/优化项可复制/AI 解读区)。
- 缺失源降级标注(尚未映射 cache_hit 索引的源 → dimension_notes 风格说明覆盖范围;EdgeOne 已映射,无需降级)。- 回归测试交付:明细/聚合既有行为回归(新端点与规则引擎仅新增、不改既有日志查询路径),含跨源/跨层口径对照与 golden 回放锁定。- 响应预留 `summary` 字段(AI 解读后置,复用 `llm` 包,env 开启)。

### Out of Scope

- 定时看护(CDN 版 diagwatch)——结构可复用,后续立项。
- 缓存规则一键下发到云(只给建议,不碰云 API)。
- 独立缓存分析页面 / 多窗口历史趋势(只对比前一等长窗口)。
- UA / 边缘节点粒度命中率(维度集本期固定为域名/URI/状态码)。
- WAF/SLB 命中率分析(本期仅 CDN)。

## Success Criteria

- [ ] CDN Tab 出现「缓存分析」入口,手动触发后 ≤ 2 帧窗口聚合(当前窗 N 次维度聚合 + 前窗 1 帧)返回分析结果;窗口时长有上限,扫描量有预估/拦截。- [ ] 结果包含:请求命中率(全请求/可缓存两档)+ 字节命中率(双口径:全请求字节命中率与可缓存字节命中率,定义见 Innovation)、域名命中率 Top 8(按口径分列或加角标;总览命中率明确为"已覆盖源命中率")、未命中 URI TOP(查询串归一后,全局 Top N(默认 5),标注归属域名;host×uri 二维聚合不承诺,"每域名前几"列为后续增强)、状态码分布(4xx/5xx 占比;状态×cache_hit 二维交叉列为后续增强)、结构化优化项(非优档按未命中流量占比降序 Top 5,优档允许 0 条;含域名/URI 前缀 + 建议动作 + 未命中流量占比 + 可信度分级,标注"建议,执行前请验证")。- [ ] 命中率口径与 `cache_hit` 分布聚合一致(同一时间边界 + 同一执行批次并发查询下可复现)。- [ ] 前窗对比给出命中率变化(↑↓),卡面标注"对比基期:前一 N 分钟"与"基于 X/Y 源"(含缺失源);缺失源(EdgeOne 已映射)降级标注,页面不白屏;明细/聚合既有行为回归通过。- [ ] 规则引擎纯函数单测覆盖:双命中率计算、档位判定、gap 检测、优化项生成;覆盖率 ≥ 80%;响应预留 `summary` 字段。
