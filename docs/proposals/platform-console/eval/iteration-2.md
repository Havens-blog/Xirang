3. **证据 → 成功标准**：SC 集合可测性显著提升（401 过期独立 SC、403 SC、走查清单化、待验项退出机制）。但发现一处修订引入/遗留的直接矛盾：Key Scenarios 的缺口处置口径与改写后的 SC-2/处置门不一致（CONTRADICTION-2，见 D9/D10）。
4. **自我矛盾检查**：
   - 上轮 CONTRADICTION-1（SC-2 ↔ 处置门）在 SC-2、处置门、迁出前置门三处已对齐——但在第四处（Key Scenarios「错误情况」）仍残留旧口径「仅适用前两类」，与「不适用 UI 降级」直接冲突。**CONTRADICTION-2 成立**。
   - 上轮 B2（Phase 0 无计划）已由「Phase 0 执行计划」整体解决（owner/时间盒/产出物/退出判据/失败分支齐备），但四项产出物中 ③（租户语义）④（登出链路）两项无失败分支——失败分支只覆盖 ①②。
   - 时间估算新增，但分项和（5.5–6.5 人周）与总项（4–6 人周）算术不一致。
   - 租户风险在 Constraints 被宣布为「最高优先风险」，但风险登记表无对应行——声明与登记脱节。

#### SC 一致性深查（聚类 + 组内双向推导，迭代 2 复检）

**Cluster A（登录/会话域）**：SC-1 ↔ SC-4 ↔ SC-5 ↔ SC-8 × InScope(登录登出/401 切换)
- SC-8 显式区分过期路径与主动登出链路——上轮 A24 的链路混同已修复。
- SC-1 两档验证口径与 InScope 四流程交付一致；SC-5 宿主口径是 SC-1/SC-4 的加严，兼容。
